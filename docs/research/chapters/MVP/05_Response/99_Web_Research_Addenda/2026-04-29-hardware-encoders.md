## §A NVIDIA NVENC 8th-gen Lovelace (RTX 4000) presets + session limits

The 8th-generation NVENC engine is the Ada Lovelace baseline (RTX 4000 series, plus the L4 / L40 / L40S datacenter SKUs). It introduced AV1 hardware encode (the first NVENC generation to do so), kept H.264 / HEVC parity, and scaled engine count by SKU: RTX 4060 / 4060 Ti / 4070 = 1 NVENC; RTX 4070 Ti / 4080 / 4080 Super = 2 NVENC; RTX 4090 = 2 NVENC + 1 NVDEC. The preset matrix exposed via Video Codec SDK 12.x is the canonical seven-preset ladder P1 (fastest) → P7 (slowest, highest quality) with three tunings (`hq`, `ll` low-latency, `ull` ultra-low-latency) and four rate-control modes (`constqp`, `vbr`, `cbr`, `vbr_hq`). HelixPlay's C27 §3 codifies the streaming-tier binding as `P4 + ull + cbr` for H.264 / HEVC / AV1 with `lookahead=0`, `b-frames=0` (P-only GOP), `aq-strength=8`, and `tuning-info=ull` — the configuration that holds the 7-frame / 117 ms E2E latency floor across all three codecs (HC-3). The 8th-gen consumer-driver session limit is **5 simultaneous encode sessions** on GeForce; the RTX PRO / Quadro / Studio drivers + datacenter SKUs lift the limit (the [keylase/nvidia-patch](https://github.com/keylase/nvidia-patch) project documents the limit and the legitimate Studio / Quadro / Tesla path that lifts it).

## §B NVIDIA NVENC 9th-gen Blackwell (RTX 5000) presets + session limits

The 9th-generation NVENC engine launched with Blackwell in 2025-Q1 and ships in the RTX 5000 series, plus the RTX PRO 6000 Blackwell line. The headline 2026 features (codified into C27 §3) are: **(1)** 10-bit H.264 hardware encode with 4:2:0, 4:2:2, and 4:4:4 chroma — industry-first on a hardware encoder; **(2)** 4:2:2 chroma encode for HEVC + AV1 (matching Intel QSV's previously unique 4:2:2 capability); **(3)** AV1 Ultra High Quality (UHQ) tuning that costs ~5-15% extra encode time for an additional ~5% BD-rate quality vs the existing P7; **(4)** lookahead level for AV1; **(5)** ~60% faster encode-throughput on RTX 5090 vs RTX 4090 (verified ~75-109% in independent Puget benchmarks for 10-bit H.264); **(6)** three Gen-9 NVENC engines on RTX 5090 (vs two on Lovelace top SKU) and RTX PRO 6000; **(7)** the same P1–P7 preset ladder + `ull` tuning as 8th-gen, preserving HelixPlay's binding `P4 + ull + cbr` configuration without breaking change; **(8)** the same 5-session consumer-driver limit as 8th-gen unless on RTX PRO / Studio / datacenter drivers. NVENC engine count by SKU: RTX 5050 / 5060 / 5060 Ti / 5070 = 1; RTX 5070 Ti / 5080 = 2; RTX 5090 = 3.

## §C AMD AMF on RDNA3 + RDNA4 — RX 7000 / 8000 / 9000

AMD's hardware-encoder posture in 2026 is the RDNA3 → RDNA4 generation transition: **RDNA3 (RX 7000 series, VCN 4.0)** carries dual media engines on top SKUs (RX 7900 XT / 7900 XTX), single engine on lower SKUs, hardware H.264 / HEVC / AV1 (I + P frames only — no AV1 B-frames), and the AMF SDK's six usage modes (`Transcoding`, `Ultra Low Latency`, `Low Latency`, `Webcam`, `HQ`, `HQLL`). **RDNA4 (RX 9000 series, VCN 5.0, 2025-Q1 launch)** is the meaningful upgrade: AV1 B-frame support (the defining VCN 5.0 capability), +25% H.264 low-latency quality, +11% HEVC quality, +50% AV1 + VP9 decode throughput, dual media engines on RX 9070 / 9070 XT, single engine on RX 9060 + below, and **no theoretical session limits** on consumer drivers (AMD's competitive response to NVIDIA's 5-session limit). HelixPlay's C27 §4 binds the AMF streaming configuration as `Usage = ULTRA_LOW_LATENCY`, `LOWLATENCY_MODE = true`, `QualityPreset = SPEED`, `MaxConsecutiveBPictures = 0` for streaming (P-only GOP); the recording path uses `Usage = HQLL` with `MaxConsecutiveBPictures = 3` for the +25% / +11% quality jump on RDNA4.

## §D Intel QSV on Arc Battlemage + Xe2 iGPU — ULL preset

Intel's Quick Sync Video (QSV) hardware-encoder line in 2026 spans two surfaces: **(1)** the Arc Battlemage discrete GPU line (Arc B580 + B570, launched 2024-12) on the Xe2 architecture, with dual MFX media engines, hardware H.264 + HEVC + AV1 + VP9 decode + 4:2:2 10-bit HEVC + AV1 encode, and 8K60 10-bit HDR encode capability — Intel's key differentiator (only Intel iGPUs + Arc cards support 10-bit 4:2:2 HEVC); **(2)** the Xe2 integrated GPU line (Lunar Lake / Arrow Lake / Panther Lake mobile + desktop) carrying the same media-engine generation for low-power host scenarios. The Ultra-Low-Latency (ULL) tuning is the binding C27 streaming preset: the IEEE / arXiv 2025 study (D1) measured **5 frames / 83 ms E2E latency at 4K60 for HEVC and AV1 with no significant additional RD penalty vs Low-Latency tuning** — the lowest of any vendor surveyed. The compatibility caveat (CZ-2) is that Intel's ULL B-frame structure is non-standard and may affect downstream decoders; HelixPlay's C27 §5 codifies P-only GOP for streaming, eliminating the compatibility concern. Session limits on Intel QSV are documented at "no theoretical limit" (D5 + D6) on consumer + workstation hardware — unlike NVIDIA's consumer driver, Intel does not artificially gate concurrent encodes. The oneVPL / VPL runtime is the canonical API surface (C27 §5 binds to oneVPL 2.10+ via Go cgo wrapper).

## §E Apple VideoToolbox — Apple Silicon M-series

Apple's VideoToolbox framework on Apple Silicon M-series chips (M1 → M5 in 2026) provides hardware H.264 + HEVC + ProRes + ProRes RAW encode + decode, with AV1 capability tracking the chip generation: **M3 / M4 = AV1 decode-only** (no hardware AV1 encode); **M5 (2026-Q1 launch) + M5 Pro / Max (2026-03) = first Apple Silicon AV1 hardware encode** SKUs. ## §G B-frame support per-vendor + per-codec (AV1 B-frames new in 2026)

B-frame support is non-uniform across vendors and codecs in 2026, and HelixPlay's C27 §3 codifies the matrix (binding for the GOP structure of streaming + recording paths):
