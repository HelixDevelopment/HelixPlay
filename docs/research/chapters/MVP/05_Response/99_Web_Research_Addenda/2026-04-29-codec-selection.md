## §A H.264 (AVC) profiles + 2026 hardware encode status

H.264 is HelixPlay's universal-fallback codec — the only video codec mandatory-to-implement in WebRTC (RFC 7742 §5), with hardware decode coverage so close to 100% that it dictates the universal tier of the codec ladder regardless of efficiency. C26 §3 codifies the profile floor (Constrained Baseline Profile Level 1.2 mandatory; Constrained High Profile Level 1.3 SHOULD-support; Main + High profiles enabled where the host hardware supports them and the client signals capability) and §4 codifies the hardware-encode posture: NVIDIA NVENC 8th-gen Lovelace (Ada) + 9th-gen Blackwell (RTX 50) including the new 10-bit H.264 path, AMD AMF on VCN 4.0 (RDNA3) / VCN 5.0 (RDNA4) with the 25% low-latency H.264 quality jump, Intel QSV on Arc Alchemist + Arc Battlemage with the Ultra-Low-Latency (ULL) tuning that keeps E2E latency to 5 frames at 4K60. The chapter elaborates the WebRTC profile-string handshake (`profile-level-id` SDP attribute, `packetization-mode 1` requirement) so a Chrome / Firefox / Safari / native client always negotiates a viable H.264 path back to the host, even when HEVC + AV1 are unavailable on the client or the path.

## §B HEVC (H.265) Main / Main10 + 2026 hardware encode status

HEVC is HelixPlay's standard tier — the codec the host emits when the client signals HEVC decode (Apple devices natively, ~57% of Android handsets via hardware decoder, ~78% of iPhone requests, modern Windows + macOS native players, and Edge on Windows at 56% of session-share). The chapter pins the profile floor at HEVC Main + Main10 (Main10 carries the 10-bit HDR path C32 elaborates), and the hardware-encode floor at NVENC since Maxwell-2 (GTX 9-series) / AMD VCE since Polaris / Intel QSV since Skylake, with 4K60 real-time operating at 2-3% GPU utilisation overhead on RTX 4000+ class hardware. The 2026-Q1 wrinkle that C26 §5 codifies is the HEVC Advance / VCL Advance rate adjustment — the 25% royalty-rate increase that takes effect 2026-01-01 for new licensees signing after 2026-06-30, deferred from the original 2025-12-31 deadline. HelixPlay's licensing posture (C26 §11 + §I below) factors this directly into the cost projection of the standard tier.

## §C AV1 — vendor matrix + 2026 hardware decode adoption

AV1 is HelixPlay's premium tier — the codec the host emits when the client signals AV1 hardware decode and the host has Lovelace-or-newer NVENC / RDNA3-or-newer AMF / Arc-or-newer QSV / M5-Pro-or-newer VideoToolbox. The 2026 hardware-decode landscape is the inflection point: ~88% of Chrome / Edge / Firefox sessions on desktop + Android decode AV1 in hardware (per WebCodecs Fundamentals dataset of 1M+ devices), up from ~25% in 2024. iOS Safari is the holdout (~33% session-share via the iPhone 16 + 17 hardware-decode line), and macOS Safari sits at ~24% (Apple Silicon M3 + later natively decodes AV1 via VideoToolbox; Intel Macs and pre-M3 Apple Silicon do not). The cross-platform combined coverage of "AV1 + HEVC" reaches 99.73% of sessions, which is the universal-coverage threshold C26 §6 codifies for the multi-codec selection algorithm.

## §D VVC (H.266) — 8-10× complexity + no real-time hardware encode (Insight #8)

VVC is the post-HEVC ITU-T / ISO standard, finalised 2020, formally added to the DVB broadcast specification 2022. Its compression efficiency is the best of any codec evaluated here — ~78% bitrate savings vs H.264 at 8K (vs AV1 ~63% and HEVC ~53%), and ~46% bitrate savings vs AV1 at 8K. **But the encoding-complexity penalty makes it operationally unviable for HelixPlay's MVP**: 8-10× HEVC encode complexity, which transitively means roughly 10× H.264 encode complexity (HEVC itself is ~2× H.264 encode complexity). The fastest current open-source software encoder, Fraunhofer HHI's VVenC (versioned in the v1.x-2.x line on its GitHub), tops out at ~280× faster than the VTM reference at the medium preset for HD4K — but that floor is still orders of magnitude slower than real-time at 4K60. As of 2026-Q2, no consumer GPU silicon ships with a real-time VVC hardware encoder; broadcast-class encoders ship from MainConcept + Allegro DVT + MulticoreWare's x266, but they target 8K60 broadcast head-end at server prices, not interactive cloud gaming. Browser support is zero across Chrome / Firefox / Edge / Safari as of 2026-03. C26 §6 and Master Plan Insight #8 codify the deferral: VVC is **out-of-scope for HelixPlay MVP**; revisit no earlier than 2028 when consumer hardware encode + browser decode begin shipping.

## §E Per-codec quality / bandwidth trade-offs (rate-distortion comparisons)

The codec-selection logic in C26 §6 is rate-distortion-aware: at the same target perceptual quality (VMAF / MOS), VVC > AV1 > HEVC > H.264 in compression efficiency, but the differences are non-uniform across resolution. The 2024-2026 academic + industry benchmark consensus places the BD-rate ladder vs H.264 as: **VVC ~ 78% bitrate saving (8K) / 59% (FHD); AV1 ~ 63% bitrate saving (8K) / 33% (FHD); HEVC ~ 53% bitrate saving (8K) / 14% (FHD)**. The bandwidth-budget rows in C26 §10 derive from these ratios — at 1080p60 SDR target VMAF ≥ 90, H.264 baseline = 6-10 Mbps, HEVC = 4-7 Mbps (~30-40% reduction), AV1 = 3-5 Mbps (~50% reduction), VVC = ~2-3 Mbps (deferred for MVP per §D). At 4K60 SDR / HDR10 target VMAF ≥ 92, H.264 = 25-40 Mbps, HEVC = 15-25 Mbps, AV1 = 10-18 Mbps, VVC = ~6-10 Mbps (deferred). The cloud-gaming-specific framing carries the additional latency-penalty input from §H — AV1 incurs 1-3 frames of additional encode latency vs HEVC on NVENC, vendor-dependent (CZ-2).
